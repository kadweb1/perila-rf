# Руководство по работе с репозиторием

## Структура проекта

Это статический сайт, собираемый с помощью Gulp. Страницы находятся в `src/*.html`, а общие HTML-фрагменты — в `src/html/` (например, `header.html` и `footer.html`). Стили размещены в `src/assets/scss/`, точка входа JavaScript — `src/assets/js/app.js`, изображения и шрифты — в `src/assets/img/` и `src/assets/fonts/`. Конфигурация и задачи Gulp находятся в `gulp/config/` и `gulp/tasks/`. Результат сборки записывается в `dist/`; изменяйте исходные файлы, а не результат сборки.

## Команды для разработки и сборки

- `npm install` — устанавливает зависимости из `package.json`.
- `npm run dev` — собирает сайт, запускает BrowserSync и отслеживает изменения исходных файлов.
- `npm run build` — очищает `dist/` и создаёт production-сборку.
- `npm run zip` — создаёт production-сборку и упаковывает её в ZIP-архив.
- `npm run deploy` — запускает `gh-pages` для `dist/`; перед запуском убедитесь, что команда доступна и публикация необходима.

Production-сборка также обновляет `gulp/version.json` для управления кешированием ресурсов. Проверьте это изменение перед коммитом.

## Стиль кода и именование

Пишите любой код в табуляцией размером 4. Не пишите html-элементы и css в одну строку, всегда пишите вниз. Использовать методологию БЭМ.

## Стиль кода css / scss / sass

В css делать отступ между классами. Объединять стили по БЭМ-смыслу и писать комментарии с названием БЭМ-элемента над началом его стилей caps-lock. К примеру, перед классом .video-vidget пишем комментарий // VIDEO-VIDGET. Если это scss или sass обязательно используй препроцессор для написания классов через &.

## Стиль кода html

Добавлять аттрибуты aria-label, alt. Не добавлять аттрибуты width, height, id. Аттрибут id добавлять только в случае если нужно стилизовать через css или к этому элементу должен идти скролл.

## Стиль кода js

В js создавайте функции через function declaration. Отдельные команды для линтинга и форматирования не настроены.

## Проверка изменений

Тестовый фреймворк и команда запуска тестов не настроены. После изменений выполните `npm run build`, проверьте сгенерированные страницы и используйте `npm run dev` для проверки затронутой вёрстки и интерактивности в браузере. При соответствующих изменениях проверьте адаптивность и загрузку ресурсов.

## Коммиты и запросы на слияние

История Git в этой копии недоступна, поэтому установленное соглашение о сообщениях коммитов определить нельзя. Используйте краткие заголовки в повелительном наклонении, описывающие изменение. В запросе на слияние опишите изменение и выполненные проверки, укажите связанную задачу и приложите скриншоты, если изменился внешний вид.
